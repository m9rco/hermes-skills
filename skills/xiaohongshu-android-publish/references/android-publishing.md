# Android 图文输入与平台功能

## 中文多行输入

附带的 `scripts/android/prepare_note_input.py` 只准备参数；Java helper 只在已打开的小红书编辑页填写标题/完整正文并读回，不点发布、不选择话题。需要当前 `rendered_post.json` 中的 `post_id`、`title`、`caption`，以及明确的 ADB 路径、设备 serial、已验证的远端 JAR 路径。

在已验证存在旧 `/system/bin/uiautomator` 包装器参数重组问题的设备上，明确使用 `--launcher app-process`。此分支使用同一系统 Launcher 和既有环境，保留空格、换行、引号、emoji；不修改系统包装器。其他设备先核查现有兼容工具，不把该兼容分支当所有 Android 的要求。

消费 prepare 产物中的**完整 `adb_argv` 数组**，使用 `subprocess.run(argv, shell=False)`；不手抄正文、不 `split()` 命令、不用 JSON 字符串充当 shell 转义。一次输入必须看到对应 post 的 `SHENQI_INPUT_RESULT` 为 `filled_and_verified`，并且标题/正文实际读回 hash 与本次输入阶段的预期相符。若使用已验收的原生话题前缀模式，成功仅证明前缀输入；它的 hash 不能代替最终完整 caption。JUnit OK、RC0 和正文前缀都不足以证明全文成功。

helper 使用 `ACTION_SET_TEXT` 写入纯文本。先完成所用模式的纯文本输入（正式全文或已验收的准备前缀），再通过原生候选添加平台话题。若之后再次整段填入正文，原生话题关联可能丢失，应将先前的话题核验作废并重新检查。helper 的文本 hash 只核验文本，不能检测富文本 span 或 topic ID。

已有草稿不能默认直接重跑填空工具。某版 helper 通过占位 **text**（例如“添加标题／添加正文”）定位；填入内容后，XML 的 **hint** 仍相同，但实际 text 已变，原 selector 可能无法命中。先核真实 `SHENQI_INPUT_RESULT` 的 stage/error_class 和当前字段，不用 `Errors1` 猜测是输入法问题。优先通过正常 UI 精确修正误输入；只有当前版本的实际 selector 确实可命中时才复用该工具。不要为试错反复清空全文，尤其不能在原生话题选择后整段重填。

多行正文中 `MOVE_END` 可能只到当前行尾，不能当成全文末尾再批量退格。需要修改尾部时，先取得可靠的实际 selectionStart/selectionEnd 或使用正常的精确文本范围选择；完成后核对全文。若工具设置 `ACTION_SET_SELECTION(length,length)`，也必须实际读回两端均等于全文长度，不能只凭 action 返回 true。位置不明确就停止删字，保留原件并用有写前全文校验的定点修复。

正文写入与光标设置是独立结果：helper 可能已写成功，但在 `SET_SELECTION` 返回 false 后整体报失败。保留真实 marker、stage 与 mutation-attempted 标记，不能当作零修改或盲目重跑全文。先用新鲜只读观察核标题身份、正文全文/hash 及实际 selection；若正文和文档末尾都已实际确认，可继续后续原生操作；仍不明就停止，不能用再次整段输入代替对账。

## 草稿保存与节点会话归属

保存时定位本次真实可见的“存草稿”控件及其 selector/bounds，不能沿用旧坐标。点击后仍在编辑器不代表已保存；正常退出后在草稿箱确认本篇标题和图片，再重开核对全文、声明和话题。保存状态未明时不要连续 Back；若新稿实际未存、选择状态已丢失，明确记为 lost 并从安全的新编辑器重建，不能拿曾选中当作重开后保留。

共享节点通道中的另一合法 task 消息可能重定向正在运行的 agent。续 UI 前核本 task/context 和当前实际界面；在安全检查点等另一 task 的真实终态边界，不擅自取消或修改它，不把它的 stdout 当本任务成功。接续后重核锁屏、账号和 UI 排他。认证成功后的有限显示窗口优先完成当前 UI；文档、资料与历史审计在自然的非 UI 边界交付，不人为保活或续旧 guard。

## 原生话题与关联验收

历史案例：一次已发布笔记的 `#话题` 只是正文纯文本。后续是否修复以对应项目的实际选择、持久化及公开关联回执为准；不能把历史缺陷当成工具链的永久状态，也不能把某篇成功套给其他篇，每篇仍须独立 fresh 验收。

1. 将“希望关联的话题”与正文文本分开记录，例如 `requested_topics` 与 `caption`。从已有冻结包读取时，不私自重写其文案或重新签 hash。
2. 看当前截图/可访问性结构，使用应用实际提供的添加话题入口或输入后出现的原生候选列表。搜索准确名称并选择相符条目；入口名称和坐标随版本变化，不固定复用旧坐标。
   - 有的客户端“#话题”按钮只在正文光标处插入 `#`，查询发生在正文中，并没有独立搜索框。输入前核实际 EditText 的 text/hint/focused 状态；不要把标题误当搜索框，也不要把普通推荐词当作已进入原生候选页。
   - `adb input text` 在某些设备无法输入中文；失败后不要盲试 clipboard service、binder 或 `KEYCODE_V`。可在已确认的正文光标位置，使用当前中文软键盘逐键拼音并选择明确的汉字候选，再选择应用的原生话题候选。每一步以真实界面为准。
   - 可从正式稿派生“正文＋问题、不带旧纯文本标签”的临时输入准备阶段，再由原生选择产生最终标签。该阶段的文字 hash 不是最终稿验收；最终完整文本必须与已固定的素材版本一致，必要的文案/标签变化先形成新版本。选择完成后不再整段 `ACTION_SET_TEXT`。
3. 记录所选条目名称，以及确实从平台候选项选择并返回编辑器的证据。编辑器显示颜色、正文出现井号、XML 字符串相符，都不能单独证明关联成功。
4. 保存并重新打开同一草稿，核验所选话题仍被平台保留，并复核最终全文、图片与平台声明。真实原生候选选择全过程、实际保存确认、草稿箱本篇标题/图片卡片、重开全文/话题样式及该版本提供的已选列表、管理面板或其他可靠关联信号分别留证，按各自范围综合验收。不额外强制 topic ID、可读 metadata 或编辑器内点击后导航；仅缺这些信息不能否定已有的真实选择、保存重开证据及可靠关联信号。缺真实候选选择或实际保存重开证据时仍为 `unverified`，文字/hash/颜色不能补缺，也不能反推没有关联；要求话题的发布任务此时停在草稿并报告具体缺项。草稿证据不等于公开关联，第5步另核实际笔记。
5. 在已经获准的正式发布后，可通过点击实际笔记中的话题进入对应话题页、读取关联名称/标识等只读方式完成公开验收。未公开前不能声称做过此验证。检查已发布缺陷可以只读；修改或重发旧笔记需要本次任务确实涵盖该动作。

建议在当前项目回执中分别记录 `requested_topics`、`selected_topics`、`topic_status`（`plain_text_only` / `native_selected_draft_verified` / `published_link_verified` / `unverified`）、证据路径及未验证原因。只有文字相符、缺原生记录时为 `unverified`；`plain_text_only` 需有实际用户/页面证据确认，不能由缺证据推断。这是记录约定，不是假定平台存在这些字段。

仅当用户或项目要求补选推荐话题时，在主话题选中后记录当时实际显示的一批推荐项及界面证据，逐项通过平台原生条目选择内容相关、无重复、不暗示不实经历且非无关活动的话题，并记录选择结果或未选原因。当前批次全部适合的项可选至界面实际允许的数量；不假定平台统一上限，不无限追逐后续刷新的推荐。推荐话题不承诺增加曝光。

新增推荐会改变最终 caption：已冻结稿先按项目允许的机制形成新版本，保留旧包，并核对新增后的实际完整 caption、最终 tag 清单及 SHA；不再整段 `ACTION_SET_TEXT` 抹掉关联。仅项目已有明确支持且已验收的 derivation/intent 接口，并已授权 publisher 动态补选时，才可用本篇受控 derivation 形成该允许的新版本，记录上述最终内容及来源 manifest 的前后 hash（冻结源不覆盖），再进入 intent；不得改旧 manifest、自行 re-sign 或重跑 register 绕过 worker/冻结内容门禁，也不得用旧完整 caption hash 冒充新增后的全文。当前选中、保存重开后的保留及正式发布后的公开关联分别验收，不能互相替代。

## 声明、预览、草稿

- 输入法会遮住声明等按钮。先用正常返回操作收起键盘，再依据新截图点击；不能仅依旧 XML bounds 点击被遮挡的位置。出现额外文字时回读并修正正文，不掩盖污染。
- 先识别声明当前状态。实际选中后勿再次点击把它取消；曾验证的黑色圆圈内白色勾只是一版 UI 样式，不是跨版本固定规则。
- 查看实际缩略图数量、封面、顺序、整张图的裁切和文字排版。草稿重开再检查全文、话题与声明；不能把一张已生成封面说成三张实图。
- 未授权发布的准备/排障不点击发布；不要借“验证功能”发测试帖。

## 提交与公开可见

沿用项目自己的 gate、claim、side-effect intent 和频控。提交前用新鲜 UI 核验账号与稿件。出现结果未知、断线或超时后先查原任务和真实笔记，不能清台账或等租约过期后当新帖重发。

把发布点击、提交成功/审核中、公开可见分开。原生页面/真实分享链接和运行终态可以互相印证；deeplink 打开成功、预览图、群内口头确认都不能单独替代公开证据。首次观察到公开的时间应标为 `first_public_visibility_observed`，没有服务端时间则 `server_published_at=null`。


## 中文预编辑与异步节点指令

拼音仍在输入法预编辑栏时，正文可能仍只有已核前缀加单个 `#`，小红书推荐也可能未变；这不证明按键未生效。先看本次真实输入法 composition 与明确汉字候选，提交一次准确词语，再等平台原生候选更新并选择。不要因为正文 hash 暂未变化而重输拼音，造成双重 composition。出现重复预编辑时，依据实时画面正常取消或有界清理，只接受已知查询态或完整原前缀的逐字/hash读回；确认原前缀立即停删，不用旧坐标、行尾或盲退格。预编辑状态与正文文本是两个核验对象，文本 hash 不能替代输入法画面。

节点消息会排队，动作前先核本任务最新有效回执、执行阶段及实时界面；已经完成选择/保存/公开验收后，迟到的输入或清理指令必须标记 superseded，禁止再执行。按已获授权的完整流程由当前唯一操作者用自己的实时截图与工具读回连续完成，原件可在自然边界集中回传审计；不要为逐按键重新索要主控许可，或因附件少了说明而停住已知安全的操作。实际字段、身份、控件或提交结果有疑义时才停止核对；未知提交始终只读验证，不重放保存/发布。

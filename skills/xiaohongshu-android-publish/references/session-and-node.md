# 正常会话、跨节点与幂等

## 先复用当前执行环境

读取当前项目配置/节点注册表和实际任务状态；路径、账号、serial、时区、cron/job/run/claim ID 均由当前环境提供。节点应用运行在 Mac 还是其连接的手机上要明确区分。知识沉淀不需要解锁、启动发布任务或重启代理/agent。

每台设备保持一个 UI 操作者；其他人可看已返回的原截图。对普通控件依据实际最新截图定位，不猜位置。解锁凭据及从它推导出的手势坐标属于认证材料，不能使用普通控件定位的共享方式。

接到新草稿任务但旧 guard pending、原发布执行未知时，先确认原设备/唯一操作者，对旧 state 路径恢复并验收原值，同时通过正式接口只读对账原 run/claim。确认原执行已终结、设备可接管后再编辑新稿；已解锁不能替代这些条件。

## 已授权的正常认证

仅在当前任务确实需要已锁定设备，且真实用户已授权其正常认证方式时使用。既有授权有效时不重复索要。只复用现有正常输入 callback；本技能没有设备解锁 callback，不能从示例猜密码/轨迹，也不能绕过锁屏。

附带三个原版公共模块：`normal_auth_envelope.py`、`normal_auth_transaction.py`、`normal_auth_screen_session.py`。其事务仅适用于原实现的中文划线指令协议，不适用于任意 PIN/密码。密码/指令仅在受控内存中经新公钥加密一次；对齐任务、nonce 和公钥 SHA。接收方解密一次、正常输入一次，验证 callback 必须返回字面 bool；失败不得猜测或循环重试。解密结果是原始人类字符串，不是待 `json.loads` 的对象。

封套格式以附带 decoder 为准：外层键精确为 `ciphertext_hex, algorithm, mgf1, label, key_sha256, nonce`；`algorithm=RSA-OAEP-SHA256`、`mgf1=SHA256`、`label=null`。加密内层精确为 `t,n,s`，分别绑定任务、nonce、原始人类字符串，UTF-8 JSON 编码后加密。decoder 内部解析并验证后只返回原始 `s`；transaction 不再解析该返回值或接收额外 sequence 对象。公钥 PEM SHA 与私钥导出的公钥必须一致。

任何命令、日志、技能、回执或截图注释中都不保存真实口令、序列、派生解锁坐标、私钥或解密结果。真实调用通过 Python 的进程内 API，绝不新增明文凭据 CLI。私钥与密文在 finally 清理，发送方在真实收件及哈希核实后删除本地密文；只保留状态、hash 和错误类，不记录异常值/locals。Python 释放引用不等于证明安全内存擦除。

## 有限屏幕会话

仅在实际需要较长 UI 操作时使用。先读取当前 `screen_off_timeout` 原值，再启独立、已确认存活的 watchdog，才允许有限修改；最长 1800 秒。原值来自该次真实读取，**不要把历史设备的 600000 硬编码为全局恢复值**。已解锁且账号匹配可直接启 guard，无需重新认证。

- guard 未恢复时，不延长、不换 state 路径“续命”，不并行新开认证。
- 模块只检查传入的 state 文件，不会自动发现其他路径下的 pending guard。调用者必须从当前项目的会话记录确认该设备没有其他待恢复 guard，并核对 state 的 serial、ADB 路径与当前设备一致；换路径或换设备不能当作恢复已完成。
- watchdog 的状态文件仅含无凭据的显示设置元数据，权限 0600；不继承认证材料。
- 操作结束立即调用 `restore_now`，实际原值读回一致后才记 `restored=true`、`restore_pending=false`。不可把认证事务里的 restoration callback 正常返回等同于屏幕恢复已经验收。
- 设备不可达或回读失败时保留 pending，报告具体未恢复状态；不为省事改变锁屏/安全/权限设置。
- 状态文件损坏、无法读取或 API 返回 error 时，即使某安全摘要带 `restore_pending=false`，也不能据此声称恢复或开启新会话；该布尔值不是全局恢复证明。保持 `unknown`，读取当前设备实际设置并与可信的原值/会话记录核对，仅完整匹配的最终恢复记录才可验收。

## 节点交接与后台任务

沿用已配置的传输通道和已有任务，不为一个技能创建新任务/cron。发送正文、文件使用稳定幂等 key；不确定投递结果先查原消息，不重传产生第二份。一次协调者负责发送/同步/下载，避免并行修改同一台账。

附件验收同时核对登记 sender 身份、当前任务关联、资源的 bytes 和 SHA。飞书上传 `file_key` 与消息资源 key 不一定相同，下载应读回官方消息的资源 key；图片可按“验证 sender+关联消息+精确 SHA/字节”接收。不要因资源 key 错误重传同一文件，更不能读/打印机器人环境凭据。

以调度器真实 run/execution UUID 和原 claim 作为执行身份；job ID、gateway PID、群消息承诺不能替代。沿用当前 gate 的新鲜 intent 窗口（某实现为 120 秒），不把准备草稿到触发 gate 的整个间隔误判为失效。原执行未知时只核验，不另启 worker、不直接编辑 ledger/queue，也不全局重启服务。

更新已有调度时保留原 ID、时区、触发时间与投递目标，通过正式接口更新并读回完整 prompt/字段。为一次指定日期观察临时借用 daily schedule 时，在 prompt 明确允许日期，其他日期零节点/UI动作，实际终结后停用，防止时区和 jitter 造成多跑。

## 代理与 Telegram 素材入口

优先复用已安装、已有配置的客户端；不要从“用户说 v2ray”推断 Mac 一定安装 v2rayU。Mac 可能已有 Clash，本机手机可能有 v2rayNG；记录实际使用的平台和客户端。只连接已配好的节点，不导入未知订阅或改安全权限。

四种证据分开：进程已启动、proxy endpoint 有响应、VPN/tun 已连接、Telegram 目标频道实际加载。HTTP302 或 `open tg://...` 的 RC0 不证明频道已打开；以原生页面/消息流为准。无法截图只说明当前采集失败，不未经诊断就断言 TCC 根因。`org.telegram.messenger.web` 包名本身不能证明是网页套壳。

可在既有已登录会话打开用户指定频道；遇实际登录/OTP 页保留该状态，不猜账号/验证码、不提取会话。不要跟随广告或向频道管理员发消息。成功加载就先完成主任务和屏幕恢复，不为追求大素材包拖延会话。
